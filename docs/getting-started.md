# Getting started

Run the stack on a machine with Docker, then load a small table and hit every endpoint. The first successful path is:

```bash
git clone https://github.com/ccheitor/data-lake-api.git
cd data-lake-api
make up
make seed ROWS=200000
make test
```

`make up` builds the API image, starts the stack, and polls `GET /health` until Trino, Redis, and object storage all report ok. Trino often needs 30–60 seconds. The wait script gives up after 5 minutes.

`make seed` drops and recreates `iceberg.payments.transactions` and writes synthetic rows. `ROWS=200000` is enough to click around. The default, `ROWS=2000000`, is what the published load test used.

`make test` checks auth, pagination, masking, the cache, and a presigned Parquet download.

## Prerequisites

You need Docker Engine with Compose v2, `make`, `curl`, and Python 3 (the smoke test uses it to read JSON). Git is only needed to clone. Plan on about 6 GB of free RAM and a few GB of disk for images. The running containers are limited to about 5.2 GB in total.

| Environment | What to install | Notes |
|---|---|---|
| Linux | Docker Engine and the Compose plugin, plus `make`, `curl`, `python3` | If your user is not in the `docker` group, prefix targets with `DOCKER='sudo docker'` |
| macOS (Intel or Apple Silicon) | Docker Desktop, Xcode Command Line Tools (`make`, `git`) | Give Docker Desktop at least 8 GB of RAM. Images are multi-arch, so Apple Silicon works |
| Windows | WSL2 with Ubuntu, then Docker Desktop using the WSL2 backend | Run git, make, and the shell inside Ubuntu. Do not clone the repo under `/mnt/c` |

Every image publishes `linux/amd64` and `linux/arm64`. The same Compose file runs on an x86 laptop and on an Arm VM.

### Linux

Ubuntu or Debian:

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker "$USER"
sudo apt-get install -y make git python3 curl
```

Open a new shell so the `docker` group applies, then `docker compose version` should print v2. On other distributions, install Docker Engine from Docker's documentation and confirm `docker compose` works. The older Python `docker-compose` v1 binary is not what this repo uses.

### macOS

Install [Docker Desktop](https://www.docker.com/products/docker-desktop/) and the command-line tools (`xcode-select --install`), which provide `git` and `make`.

In Docker Desktop, open Settings, Resources, and set memory to 8 GB or more. The Trino container alone is limited to 3 GB. Apple Silicon pulls the arm64 manifests; you do not need to set a platform.

`make loadtest` runs k6 with `--network host`. That mode matches the Linux VM, not Docker Desktop. On a Mac, install k6 on the host (`brew install k6`) and follow [Performance](performance.md), or run the Locust file on the host. `make up`, `make seed`, and `make test` do not need host networking.

### Windows with WSL2

The scripts are bash. `scripts/smoke-test.sh` uses GNU `date`. The supported Windows setup is Ubuntu on WSL2, with Docker Desktop's WSL2 integration enabled for that distro.

1. Install WSL2 and Ubuntu (`wsl --install` in an elevated PowerShell, then reboot if Windows asks).
2. Install Docker Desktop and turn on **Use the WSL 2 based engine**. In Docker Desktop, Resources, WSL integration, enable the Ubuntu distro.
3. Open the Ubuntu terminal, not PowerShell, and install make:

   ```bash
   sudo apt-get update && sudo apt-get install -y make git python3 curl
   ```

4. Clone the repository on the Linux filesystem, for example `~/src/data-lake-api`. A checkout under `/mnt/c/...` is slow because every file crosses into the Windows drive.
5. Give Docker Desktop at least 8 GB of RAM (Settings, Resources). WSL2 also respects `%UserProfile%\.wslconfig` if you set `memory=` there. The stack cannot use more RAM than the WSL VM.

Then run the same `make up`, `make seed`, and `make test` commands from the Ubuntu shell.

## Step by step

From a clean clone:

```bash
cp .env.example .env   # make up does this if .env is missing
make up
```

When it returns, these URLs work on the host:

| URL | What |
|---|---|
| http://localhost:8000/docs | Swagger UI generated by FastAPI |
| http://localhost:8000/health | Dependency checks, no API key |
| http://localhost:9001 | Object storage console. User and password come from `.env` |
| http://localhost:8080 | Trino UI. Any username, no password in this demo |

Load data. The seed container is profile `tools`, so it is not left running:

```bash
make seed ROWS=200000 DAYS=30
```

`DAYS` is the history window ending today, inside the container clock. Then:

```bash
make test
```

A passing run prints `PASS` for health, a 401 without a key, cursor order, masked and clear card numbers, a cache miss followed by a hit, and a presigned download. It ends with `All smoke tests passed.`

Try one call yourself. Dates must cover data you just generated and stay within 31 days:

```bash
FROM=$(date -d '-7 days' +%F 2>/dev/null || date -v-7d +%F)
TO=$(date +%F)
curl -s -H 'X-API-Key: dev-analyst-key' \
  "localhost:8000/v1/transactions?date_from=$FROM&date_to=$TO&limit=2"
```

Default keys are in `.env.example`: `dev-analyst-key` (masked) and `dev-admin-key` (clear card and CPF). Change them before any machine is reachable from a network you do not trust.

Stop the stack with `make down` (volumes stay, so the table is still there next time) or `make clean` (deletes the volumes).

Other day-to-day targets are in [Configuration](configuration.md).

## Troubleshooting

### `make up` exits before the API is healthy

`scripts/wait-healthy.sh` curls `http://localhost:8000/health` for up to 5 minutes. On failure:

```bash
docker compose ps
docker compose logs trino --tail 80
docker compose logs api --tail 80
docker compose logs iceberg-rest --tail 80
```

`/health` returns 503 while any check is failing. The body names the dependency: `trino`, `redis`, or `object_storage`. Trino is almost always the slow one. Its healthcheck waits until `GET /v1/info` reports `"starting": false`.

If `minio-init` exits non-zero, the buckets were not created and the API's object-storage check fails. Read `docker compose logs minio-init`. The init container must reach `http://minio:9000`. Host access to `localhost:9000` can succeed even when container-to-container traffic is dropped; see networking below.

### Out of memory, or Trino is OOM-killed

The published load-test notes record this failure mode: a 2 GB limit on the Trino container together with the image's default heap (a large fraction of that limit) got the JVM killed under load, and every request failed. The repo now sets `-Xmx1536M` inside a 3 GB container limit. Heap and container limit have to move together. Raising only `-Xmx` past what cgroup memory allows brings the OOM back.

If `docker compose ps` shows Trino restarting, or `dmesg` mentions an OOM kill:

- Docker Desktop memory is too low. Set 8 GB or more.
- Another workload on the machine is competing. `make down` other projects.
- Do not lower `mem_limit` on Trino below 3 GB without also lowering `-Xmx` in `trino/etc/jvm.config` and `query.max-memory` in `trino/etc/config.properties`.

The API container is 768 MB with two uvicorn workers. A huge export is streamed to a temp file in 50,000-row chunks, so the API limit is not what holds the full result. The seed container is 2 GB and commits every 250,000 rows so a multi-million-row load does not need a larger machine.

### Ports already in use

Compose publishes:

| Host port | Service |
|---|---|
| 8000 | API |
| 8080 | Trino |
| 8181 | Iceberg REST |
| 9000 | S3 API |
| 9001 | Storage console |
| 6379 | Redis |

Find the listener (`ss -ltnp` on Linux, or Docker Desktop's port view) and stop it, or change the left-hand side of the port mapping in `docker-compose.yml` (`"8000:8000"` becomes `"18000:8000"`). If you move 8000, call the smoke test with `BASE_URL=http://localhost:18000 make test`. If you move 9000, set `S3_PUBLIC_ENDPOINT` to that same host port. Presigned URLs are built from `S3_PUBLIC_ENDPOINT`, not from the in-cluster address.

### Permission denied on the Docker socket

`dial unix /var/run/docker.sock: connect: permission denied` means the user is not in the `docker` group. Either log in again after `usermod -aG docker`, or run `make up DOCKER='sudo docker'` (and the same prefix on `seed`, `ps`, `logs`, `down`).

### Containers cannot reach each other

Symptoms: `minio-init` logs `i/o timeout` dialing `minio:9000`, or the API logs Trino connection errors, while `curl localhost:9000` from the host works. Published ports are proxied by Docker; traffic between containers uses the bridge.

Check `docker compose ps` and, from a container on the project network, `python -c` or `curl` against `http://minio:9000/minio/health/live`. On Linux, a host firewall or a second iptables backend (nft and legacy both loaded, with FORWARD policy DROP only on one of them) can drop bridge traffic. `sudo iptables -L FORWARD` and `sudo iptables-legacy -L FORWARD` should not drop the compose bridge. Corporate VPN clients sometimes do this. Restarting Docker after the VPN connects is a common fix. This is a host problem; the Compose file does not disable inter-container communication.

### `make seed` fails or the smoke test finds no page

Seed must run after the catalog is up (`make up` first). It always passes `--replace`, which drops the table. If you needed the old data, it is gone.

The generator's "today" is the container clock, usually UTC. `make test` uses the host's local date for a 7-day window. Around midnight, a host west of UTC can ask for a window that has not started inside the container yet, and the first page is empty, so the smoke test fails on `next_cursor`. Re-run `make seed DAYS=30`, or call the API with explicit dates that overlap the generated history.

`make test` also expects at least six rows in that 7-day window (it asks for `limit=5` and a cursor). A tiny seed such as `ROWS=100` over `DAYS=90` can miss that. Use `ROWS=20000` or more.

### Presigned download returns 403 or does not connect

The URL host is `S3_PUBLIC_ENDPOINT` (default `http://localhost:9000`). That host must be the one the downloader can resolve. From the laptop, localhost is correct. From another machine, set it to the reachable address before you start the API, then recreate the API container so it picks up the env (`docker compose up -d api`). A signature is bound to the host header; editing the URL after the fact invalidates it.

The `exports` bucket has a one-day lifecycle rule. An object older than that can disappear.

### `make loadtest` on Docker Desktop does nothing useful

`--network host` does not attach the container to the Mac or Windows host network the way it does on Linux. k6 then calls `localhost:8000` inside the container, where the API is not listening. Use a Linux host for `make loadtest`, or run k6/Locust on the host against `http://localhost:8000`. Commands are in [Performance](performance.md).

### Compose warns that Buildx or Bake is missing

`Docker Compose is configured to build using Bake, but buildx isn't installed` is a warning. Compose falls back and still builds the API image. Install the buildx plugin if you want the warning gone. It does not change the application.

### API returns 401, 400, or 422

401 means the `X-API-Key` header is missing or not in `API_KEYS`. 400 means the date range is inverted, longer than the cap, or the cursor cannot be decoded. 422 means a query parameter failed validation (bad date, unknown category, negative amount, limit out of range). The [API reference](api-reference.md) lists each case.
